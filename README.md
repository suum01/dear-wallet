# Dear Wallet

나에게 맞는 가계부. 기록은 가볍게, 내 돈의 흐름은 또렷하게.

AI가 소비 내역을 자동 분류하고, 소비 습관 분석과 맞춤형 예산 관리를 도와주는 개인 가계부 웹앱을 목표로 합니다. 현재 구현 범위는 아래와 같습니다.

연노란색과 세이지 그린, 직접 그린 지갑 캐릭터로 구성한 반응형 홈과 달력 내역 화면입니다. 외부 폰트·CDN·애플리케이션 의존성 없이 실행됩니다.

## 실행

Node.js 22 이상(검증: 24.22.1).

```sh
npm start
```

기본 포트는 3000이며 `PORT=3001 npm start`로 변경할 수 있습니다. 정적 호스팅 시 `npm run build`로 생성된 `dist/`만 배포합니다. 상대 경로를 사용하므로 도메인 루트와 `/dear-wallet/` 같은 프로젝트 경로를 모두 지원합니다. 서버는 개발용이며 공개 서비스의 인증·데이터 서버가 아닙니다.

## 구현한 것

- 모바일 하단 메뉴 / 데스크톱 사이드바, 320px부터 대응하는 홈
- 예산 전에는 가득 찬 원과 지출 금액, 예산 후에는 12시에서 시계 방향 사용률
- 전체 예산, 기간 경과, 남은 일수, 아직 결제되지 않은 고정비를 제외한 가용 금액
- 날짜별 수입·지출 달력, 날짜 선택 바텀 시트, 선택한 날짜에 바로 기록
- 수동 지출·수입·내부 이체 기록, 월급날/달력 집계, 기간별 전체 예산, 고정비 연결
- 한국 시간 기준 일별 금융 상식 7개 순환, 북마크, JSON 내보내기
- 실제 기록과 분리된 샘플 둘러보기(설정에서 시작)
- 접근 가능한 다이얼로그, 키보드 포커스, 모션 감소 설정 반영

첫 실행은 0원에서 시작합니다. 예시 금액은 **설정 → 샘플 데이터로 둘러보기**에서만 표시합니다. 내역은 날짜별 조회와 기록 추가·수정·삭제·삭제 취소를 지원하며, 돌아보기는 후속 구현입니다. 예산 메뉴는 현재 전체 예산/고정비 설정창을 엽니다. 자동 분류는 아직 없으며 기록은 미분류로 보관됩니다.

## 데이터 안내

현재 데이터는 `localStorage`의 `dear-wallet.v1`에만 저장됩니다. 서버 전송·로그인·기기 동기화가 없습니다. 브라우저 데이터 삭제/기기 변경 시 보존되지 않으므로 설정에서 JSON으로 내보내세요. 파일 복원 UI는 후속 작업입니다. 내보낸 파일에는 개인 기록이 들어 있으므로 저장소에 커밋하지 마세요. 저장에 실패하면 완료로 처리하지 않고 기존 데이터를 보호합니다. 샘플 모드의 수정은 실제 기록에 반영되지 않습니다.

고정비는 등록한 전체 예상 금액을 예약하고, 같은 집계 기간의 지출에 연결되면 예약에서 제외합니다. 부분 결제·고정비 변경 이력·환불은 아직 지원하지 않습니다. 고정비 예정일은 향후 캘린더 표시를 위한 정보이며 날짜가 지났다고 자동 결제 처리하지 않습니다.

## 검증

```sh
npm run check
npm test
```

선택적 브라우저 통합 검증은 Python Playwright와 시스템 Chromium이 있는 환경에서 실행합니다. 애플리케이션 실행에는 필요하지 않습니다.

```sh
# 별도 터미널에서 npm start 실행 후
python tests/browser.py
python tests/history-browser.py
python tests/edit-browser.py
```

`CHROMIUM_PATH`로 브라우저 경로를 변경할 수 있습니다. 320/375/390/430/768/1024/1440px 화면, 기록·새로고침 저장, 예산 사용률, 고정비 중복 차감 방지, 수입/이체 제외, 샘플 격리, 초과 예산, 기간 변경, 큰 금액을 검사합니다. 화면 캡처는 Git에서 제외된 `artifacts/`에 생성됩니다.

## 기획

[전체 제품 기획과 화면별 흐름](docs/product-plan.md)에 합의한 요구사항과 구현 범위를 정리했습니다. 모바일 웹부터 만들고, 완전한 PWA·계좌 대조는 이후 확장합니다.

### 작은 기능 단위로 확인하기

이번 단계는 **내역 → 날짜 선택 → 목록 확인 → 이 날짜에 기록 → 합계 갱신**입니다. `#history` 주소로 바로 열 수 있으며 새로고침과 뒤로가기를 지원합니다. 현재 예산 기간은 달력에서 강조하고 상단 합계도 해당 기간으로 고정합니다. 이전/다음 달을 탐색해도 현재 예산 기간은 바뀌지 않습니다. 달력의 작은 화면 금액은 만·억 단위로 줄이며 상세창에서는 정확한 원 단위로 표시합니다. 기록을 누르면 금액·날짜·사용처·이유·카테고리·종류·고정비 연결을 수정할 수 있습니다. 검색·파일 가져오기는 다음 단계에서 추가합니다. 스프레드시트 연결 전까지 저장 방식은 기존 브라우저 로컬 저장을 유지합니다.

### 기록 수정·삭제

날짜별 목록의 기록을 누르면 기존 값이 채워진 수정창이 열립니다. 닫기/Escape는 저장하지 않고 원래 목록으로 돌아갑니다. 날짜를 바꿔 저장하면 변경된 날짜의 달력과 목록으로 이동합니다. 분류 수정은 해당 기록에만 적용하며 자동 분류 규칙은 아직 생성하지 않습니다.

삭제는 확인 후 처리하고 행에 삭제 시각을 남깁니다. 삭제한 기록은 홈·달력·목록·고정비 결제 계산에서 모두 제외됩니다. 마지막 삭제 하나를 안내창의 실행 취소로 복원할 수 있습니다. 안내를 닫거나 페이지를 새로고침하거나 샘플 모드로 전환하면 실행 취소 기회는 끝나며, 영구 휴지통 UI는 아직 없습니다. 내보낸 JSON에는 삭제 표시가 있는 원본도 포함됩니다. 다른 창에서 바뀐 기록을 편집 중인 경우에는 덮어쓰지 않고 다시 열도록 안내합니다.

## GitHub Pages 배포

`.github/workflows/pages.yml`은 main 푸시 또는 수동 실행 시 검사 → 테스트 → 공개 파일 빌드 → Pages 배포를 수행합니다. 별도 패키지 설치나 개인 토큰은 필요 없으며, Actions의 기본 `GITHUB_TOKEN`과 Pages 배포 권한을 사용합니다.

### 최초 한 번 설정

1. [저장소 Settings → Pages](https://github.com/suum01/dear-wallet/settings/pages)를 엽니다.
2. **Build and deployment → Source → GitHub Actions**를 선택합니다.
3. [Actions의 Deploy Dear Wallet to GitHub Pages](https://github.com/suum01/dear-wallet/actions/workflows/pages.yml)에서 **Run workflow → main → Run workflow**를 실행합니다. 이미 실행 중이면 완료를 기다립니다.
4. build와 deploy가 모두 성공하면 deploy 작업의 `github-pages` 링크로 접속합니다.

기본 예상 주소는 **https://suum01.github.io/dear-wallet/** 입니다. 이 주소는 Pages 활성화와 배포 성공 후에만 접속할 수 있습니다. 최초 설정 전에 실행한 워크플로가 실패했다면 설정 후 다시 실행합니다. 이후에는 main에 올릴 때마다 자동 갱신됩니다.

### 배포 결과 로컬 검증

```sh
npm run check
npm test
npm run build
npm run preview
```

preview는 기본적으로 `/dear-wallet/` 경로, 4173 포트에서 `dist/`를 제공합니다. 루트 배포 검증은 `BASE_PATH=/ npm run preview`를 사용합니다. `BASE_URL`을 지정하면 기존 브라우저 테스트도 배포 경로에서 실행할 수 있습니다.

```sh
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/browser.py
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/history-browser.py
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/edit-browser.py
```

배포 파일에는 웹 화면용 HTML·CSS·JavaScript·아이콘·매니페스트만 포함됩니다. 로컬 기록, 내보낸 JSON, 테스트 결과, 문서, 환경변수 파일은 포함하지 않습니다. 기존 개발 주소에 저장된 기록은 새 배포 주소로 자동 이동하지 않습니다. 배포 후에도 기기별 브라우저 저장이며 구글 시트 동기화는 아직 연결되지 않았습니다.
