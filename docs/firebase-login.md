# 계정 로그인과 홈 진입

로그인 화면 → Google 계정 선택 → Firebase Authentication 세션 → 본인 UID의 Firestore 기록 조회 → 홈 순서로 동작한다. 처음 가입한 계정은 집계 기준을 선택한 뒤 홈으로 간다. 로그인·조회가 실패하거나 취소되면 홈을 표시하지 않는다. 구글 계정 비밀번호를 앱에서 받지 않는다.

최초 HTML부터 로그인 화면 대신 큰 노란 지갑 캐릭터를 보여준다. SDK 초기화·세션 확인·로그인 팝업 대기·계정 기록 조회 동안 이 로딩 화면을 유지하고, 로그아웃 상태가 확인된 경우에만 Google 로그인 화면을 표시한다. 캐릭터의 투명도는 0.74이며 안내 글씨는 투명하게 만들지 않는다. 동작 줄이기 설정에서는 캐릭터와 점 애니메이션을 멈춘다. 로딩 중에도 샘플/기존 기기 기록으로 이동할 수 있다. `tests/loading-browser.py`에서 느린 SDK·인증·조회 상황과 320~1440px 화면을 검증한다.

## 현재 준비 상태

로그인 UI, 실제 Firebase SDK 어댑터, 계정별 캐시·Firestore 저장 경로, 첫 설정, 기존 기록 가져오기, 로그아웃, 오류 처리는 구현되어 있다. `src/firebase-config.js`에는 사용자가 제공한 **dear-wallet-96f8c** 웹앱 설정을 등록했다. Analytics는 초기화하지 않는다. 사용자가 Google 로그인 제공자, 승인 도메인, Firestore 생성·보안 규칙을 설정한 뒤 실제 로그인과 홈 진입이 정상 동작한다고 확인했다. 설정 전 버튼은 연결 준비 상태를 안내하며 인증 성공으로 가장하지 않는다. 기존 기능은 ‘이 기기 기존 기록 열기’, 샘플은 ‘먼저 둘러보기’로 접근할 수 있다.

자동 브라우저 테스트는 Firebase 어댑터를 모의 모듈로 대체해 로그인 결과와 계정 데이터 동작을 검증한다. 실제 SDK는 공식 npm 패키지를 잠금파일로 설치하고 빌드에 번들링한다. 실제 Google OAuth 로그인과 홈 진입은 사용자가 확인했다. 자동화된 실제 계정·교차 계정 접근 검증과 보안 규칙 에뮬레이터 검증은 별도로 수행해야 한다. 개발 환경에서는 등록된 공개 설정으로 실제 Firebase SDK 초기화와 로그인 전 홈 숨김을 확인했다. 사용자 계정 선택·Google 승인·실제 Firestore 데이터 접근은 이 검사에 포함되지 않으며, 실제 사용자 인증을 통과했다고 보고해서는 안 된다.

## 프로젝트 관리자 설정 — 최초 한 번

1. Firebase 콘솔에서 기존 Google Cloud 프로젝트에 Firebase를 추가하거나 새 프로젝트를 생성한다. 결제 계정을 연결하지 않고 Spark로 시작한다.
2. 프로젝트 설정 → 내 앱 → 웹 앱(`</>`)을 등록한다. GitHub Pages를 계속 사용하므로 Firebase Hosting 선택은 필수가 아니다.
3. 발급된 웹 `firebaseConfig`의 `apiKey`, `authDomain`, `projectId`, `appId`를 `src/firebase-config.js`에 등록한다. 이는 브라우저에 공개되는 프로젝트 식별 설정이다. 서비스 계정 키·OAuth client secret·관리자 토큰은 넣지 않는다.
4. Authentication → Sign-in method에서 Google을 활성화하고 지원 이메일을 지정한다.
5. Authentication → Settings → Authorized domains에 `suum01.github.io`를 추가한다. 로컬에서 실제 Google 로그인도 검사하려면 로컬 도메인을 별도로 등록한다.
6. Firestore Database를 기본 `(default)` 데이터베이스로 생성한다. 테스트 공개 모드 대신 기본 접근을 거부하는 프로덕션 모드로 시작한다.
7. Rules 탭에 `firebase/firestore.rules` 내용을 적용한다. 이 규칙을 적용하기 전에는 계정 데이터 조회가 거부될 수 있으며, 앱은 오류 화면에 머문다. 인증 없는 읽기·쓰기나 전역 공개 규칙으로 우회하지 않는다.
8. GitHub Pages 자동 배포가 끝난 후 실제 브라우저에서 Google 로그인과 홈 진입, 다른 기기의 동일 계정 조회, 로그아웃을 확인한다.

시트용 OAuth client ID는 Firebase 웹앱 설정을 대신하지 않는다. Firebase에서 관리형 Google 로그인용 OAuth 설정을 구성한다. 실제 계정 선택과 권한 승인은 사용자의 브라우저에서 완료해야 한다.

## 데이터와 계정 분리

- 원격 경로: `users/{uid}/wallet/{table}__{key}` 및 `users/{uid}/account/profile`.
- 캐시: `dear-wallet.account.{uid}.v1`. 상태와 마지막 서버 기준 상태를 함께 보관한다.
- 접근 규칙: 인증된 UID와 경로 UID가 일치해야 읽고 쓸 수 있다. 다른 사용자 경로는 거부한다.
- 기존 `dear-wallet.v1`과 시트 연결 설정은 유지하며 계정 데이터에 자동으로 합치지 않는다. 계정 설정에서 ‘이 기기 기존 기록 가져오기’를 누르고 확인한 경우에만 합친다.
- 새 기기에서 같은 Google 계정으로 로그인하면 같은 UID 경로의 기록을 읽는다. 서로 다른 UID는 별도 지갑이다.
- 첫 조회는 서버에서 확인한 뒤 홈을 표시한다. 처음 계정 조회 후에는 서버 수정 시각 기준으로 변경된 문서를 조회해 전체 내역의 반복 읽기를 줄인다. 변경 시각은 서버 타임스탬프를 사용하며 경계 시각은 포함해 누락을 방지한다.
- 기록 추가·수정·삭제는 변경한 ID의 문서만 저장한다. 다른 거래 ID의 동시 추가는 덮어쓰지 않는다. 같은 기록의 동시 변경은 마지막 서버 쓰기를 따른다.
- 로컬 변경은 캐시에 먼저 보관하고 자동 전송한다. 미전송 변경은 다음 로그인 때 다시 전송한다. 네트워크 오류를 저장 성공으로 표시하지 않는다.
- 로그아웃·계정 전환 시 늦게 도착한 이전 계정 응답이 홈을 열지 않도록 세션 세대를 확인한다. 개인 기록이 들어 있는 DOM도 비운다. 캐시를 삭제하는 것과 로그아웃은 별도이며 로컬 캐시는 기기 사용자에게 접근 가능하므로 공용 기기에서는 브라우저 데이터 보관을 고려해야 한다.

## 검증

```sh
npm ci
npm run check
npm test
npm run build
npm run preview
# 별도 터미널
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/auth-browser.py
```

`tests/auth-browser.py`는 **모의 Firebase 인증·데이터 어댑터**로 320~1440px 로그인 화면, 취소, 팝업 차단, 로그인 후 홈, 세션 복원, 로그아웃, 계정 분리, 첫 가입 설정, 접근 거부 후 재시도를 검증한다. 모의 설정과 어댑터는 Playwright 네트워크 가로채기로만 주입하며 배포 파일에는 테스트 로그인 경로나 우회 플래그를 넣지 않는다. 기존 브라우저 테스트는 ‘이 기기 기존 기록 열기’를 명시적으로 선택한다.

보안 규칙 파일의 실제 Firebase 배포·에뮬레이터 검증은 아직 수행하지 않았다. 실제 Google 로그인과 Firestore 권한 검증은 관리자 설정을 완료하고 사용자의 실제 브라우저에서 진행해야 한다. 이 개발 환경에서는 Google API 네트워크 접근과 프로젝트 관리자 인증이 제공되지 않는다.
