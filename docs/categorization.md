# 사용처·내용 자동 분류

분류는 외부 AI 호출 없이 브라우저 안에서 실행한다. 사용처와 선택적인 ‘내용’을 입력할 때 결과가 바로 표시되고, 저장할 때 현재 입력값으로 확정한다. 사용처/내용/분류/수정 이력은 기존 기록 저장 경로로만 동기화하며 별도 모델 서비스로 보내지 않는다.

## 판단 순서

1. 종류가 내부 이체이면 ‘내부 이체’. 분류 기능은 거래 종류나 금액을 바꾸지 않는다.
2. 사용자가 명시적으로 기억시킨 같은 사용처·거래 종류의 분류.
3. 구체적인 구매 내용. 예: CU의 ‘치약과 세제’는 생활용품, 스타벅스의 ‘커피머신 구입’은 쇼핑.
4. 사용처에 포함된 구매 내용 또는 용도가 분명한 브랜드. 예: 김밥천국은 식비, 스타벅스는 카페.
5. 용도를 알기 어렵거나 여러 지출 용도가 섞였으면 미분류. 수입은 알기 어려운 경우 기타 수입.

편의점·대형마트·쿠팡·다이소 등 여러 종류를 판매하는 곳은 이름만으로 식비나 쇼핑을 확정하지 않는다. 지원 키워드와 브랜드는 `src/categorizer.js`에서 관리한다. 현재 구현은 키워드·사용처 규칙에 기반하므로 모든 상점이나 문장의 의미를 이해하는 것은 아니다. 알 수 없는 기록은 저장을 막지 않는다.

쏘카/SOCAR, 그린카/GreenCar, 카셰어링·렌터카·렌트카·차량 대여는 사용처와 내용 양쪽에서 ‘교통’으로 인식한다. 현재 큰 분류를 유지하며 ‘카셰어링·렌터카’라는 별도 세부분류를 저장하는 것은 아니다. 기존 미분류 기록을 수정하려면 해당 기록의 ‘자동 분류로 다시 보기’를 사용한다. [5개 앱 카테고리 조사와 확장 제안](category-research.md)을 별도로 정리했다.

‘내용’과 ‘왜 썼나요?’는 별도 필드다. 분류는 사용처와 내용만 사용하고, 지출 이유를 추측하거나 감정·동기를 분류 근거로 사용하지 않는다.

## 직접 수정과 사용처 기억

- 자동 결과는 입력창에서 바꿀 수 있다. 직접 수정하면 해당 입력 중에는 자동 결과로 덮어쓰지 않는다.
- ‘이 사용처는 다음에도 …로 기억하기’를 선택한 경우에만 개인 규칙을 저장한다. 선택하지 않으면 이번 기록에만 적용한다.
- 사용처는 유니코드 정규화·대소문자·공백·기호·일부 법인 접두사를 정리하여 비교한다. 지점명은 유지하므로 다른 지점에 무조건 확장하지 않는다.
- 지출과 수입 규칙은 분리한다. 내부 이체 규칙은 만들지 않는다.
- 기억해 둔 분류가 적용되면 ‘기억한 분류’ 배지를 표시한다.
- ‘이 사용처 기억 해제’는 현재 기록을 저장할 때 적용한다. 창을 닫으면 해제도 취소된다.
- 기존 기록은 일괄 재분류하지 않는다. 기존 기록을 열어 금액만 고쳐도 저장된 분류를 유지한다. ‘자동 분류로 다시 보기’를 누르거나 기존 자동 분류 기록의 사용처·내용을 바꿨을 때 새 판단을 적용한다.
- 개인 규칙을 추가·변경·삭제해도 과거 기록은 바꾸지 않는다.

## 데이터와 동기화

- 기록에 선택적 `description`과 `categorySource`를 추가한다. 이전 기록도 그대로 읽힌다.
- `categorySource`: keyword / merchant-rule / manual / unclassified / transfer.
- 개인 규칙은 `settings.categoryRules`에 보관한다. 규칙은 종류·정규화 사용처·표시용 사용처·카테고리·수정 시각을 가진다.
- 동기화는 규칙마다 `table: settings`, `key: categoryRule:{종류}:{사용처}`로 분리하여 전송한다. 다른 기기에서 서로 다른 사용처를 기억시킨 경우 하나의 배열로 덮어쓰지 않는다.
- 기존 Firestore 보안 규칙의 settings 문서 범위 안에서 저장하므로 새 콘솔 설정이나 권한 확대가 필요하지 않다. 기존 UID별 접근 규칙이 그대로 적용된다.
- 기억 해제는 해당 규칙 문서의 value를 null로 기록한다. 증분 조회에서 다른 기기의 삭제도 반영한다.
- 기존 시트 연결을 사용하는 경우 거래내역 탭의 기존 10열 뒤에 내용·분류방식 2열을 추가한다. 기존 행과 첫 10열은 유지한다. 기존 미지원 열이나 다른 헤더가 있으면 자동 덮어쓰지 않고 중지한다.
- 직접 기록 수정/삭제, 예산 집계, 내부 이체 제외 규칙은 변하지 않는다.

## 검증

```sh
npm test
npm run check
npm run build
npm run preview
# 별도 터미널
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/category-browser.py
```

브랜드 분류, 구매 내용 우선, 여러 용도 섞임, 미분류, 수입·이체, 정확한 사용처 범위, 한 번만 수정, 명시적 기억, 기억 해제 취소/확정, 기존 기록 유지, 설정 변경·재접속, 기기 간 규칙 병합과 기존 시트 호환을 검증한다. 자동 브라우저 테스트는 개인 기록 대신 테스트 데이터를 사용한다. 실제 Firebase 사용자 데이터에는 접근하지 않는다.
