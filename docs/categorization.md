# 사용처·내용 자동 분류

Google 로그인 후 기록을 입력하면 별도 버튼 없이 Firebase AI Logic을 통해 Google AI가 사용처와 선택적인 ‘내용’을 의미로 해석한다. 입력을 약 0.9초 멈추면 호출하고 기존 지출 14개·수입 5개 및 사용자가 확인해서 추가한 카테고리 중 하나를 고른다. 적합한 항목이 없으면 새 이름을 추천하고 추가 여부를 묻는다. [서비스 활성화와 실제 호출 확인 방법](ai-categorization.md)을 참고한다.

AI 연결 실패 시나 로컬·샘플 모드에서는 기존 브라우저 키워드 분류를 사용한다. AI 응답 전과 오류 상태의 결과는 ‘임시 분류’, 검증된 AI 응답은 ‘AI’ 배지로 구분한다. AI에는 사용처·내용·선택한 거래 종류와 추가한 카테고리 이름만 보내며 금액·날짜·계좌·로그인 프로필·지출 이유·과거 기록은 보내지 않는다.

## 판단 순서

1. 종류가 내부 이체이면 ‘내부 이체’. 분류 기능은 거래 종류나 금액을 바꾸지 않는다.
2. 직접 고른 분류, 기존 기록의 저장된 분류, 사용자가 명시적으로 기억시킨 같은 사용처·거래 종류의 분류를 우선한다.
3. 로그인된 계정에서는 사용처·내용을 기본으로 AI 해석한다. 확정한 결과는 현재 거래 종류에 허용된 카테고리인지 다시 검사한다. 미확인 새 이름은 바로 적용하지 않고 추천으로 분리한다.
4. AI를 사용할 수 없는 경우 구체적인 구매 내용 → 사용처 순서의 키워드 분류를 사용한다. 예: CU의 ‘치약과 세제’는 생활용품, 스타벅스의 ‘커피머신 구입’은 쇼핑.
5. 용도를 알기 어렵거나 여러 지출 용도가 섞였으면 미분류. 수입은 알기 어려운 경우 기타 수입. 실패해도 수동 분류와 저장은 가능하다.

편의점·대형마트·쿠팡·다이소 등 여러 종류를 판매하는 곳은 이름만으로 식비나 쇼핑을 확정하지 않는다. 내용에 반숙란을 적으면 식비를, 치약을 적으면 생활용품을 제안할 수 있다. 키워드 대체 경로도 씨유·지에스25·지에스이십오 등의 한글 이름과 반숙란·구운란을 인식하도록 보완했다. 키워드만으로 모든 상점이나 문장의 의미를 이해하지는 못한다. 알 수 없는 기록은 저장을 막지 않는다.

쏘카/SOCAR, 그린카/GreenCar, 카셰어링·렌터카·렌트카·차량 대여는 사용처와 내용 양쪽에서 ‘교통’으로 인식한다. 현재 큰 분류를 유지하며 ‘카셰어링·렌터카’라는 별도 세부분류를 저장하는 것은 아니다. 기존 미분류 기록을 수정하려면 해당 기록의 ‘자동 분류로 다시 보기’를 사용한다. [5개 앱 카테고리 조사와 확장 제안](category-research.md)을 별도로 정리했다.

‘내용’과 ‘왜 썼나요?’는 별도 필드다. 분류는 사용처와 내용만 사용하고, 지출 이유를 추측하거나 감정·동기를 분류 근거로 사용하지 않는다.

## 기록 종류별 입력과 직접 선택

| 기록 종류 | 출처 표시 | 내용 표시 | 선택 메모 표시 |
| --- | --- | --- | --- |
| 지출 | 사용처 | 내용 | 왜 썼나요? |
| 수입 | 입금처 | 수입 내용 | 어떻게 들어온 돈인가요? |
| 내 계좌 간 이체 | 이체한 계좌 | 이체 내용 | 이체 메모 |

종류에 맞춰 예시·안내·기억 문구도 바뀐다. 입력한 값은 종류를 바꿔도 유지하며, 기존 수입 기록을 수정할 때도 수입 문구를 사용한다. 저장 필드는 기존 merchant / description / reason을 유지하므로 이전 기록과 계정·시트 저장 형식은 그대로 읽힌다. 입금 경위와 이체 메모도 AI에는 보내지 않는다.

카테고리 입력 오른쪽의 화살표는 현재 입력값에 관계없이 해당 거래 종류의 전체 목록을 연다. 기본 지출 14개·수입 5개와 사용자가 저장한 같은 종류의 카테고리를 보여준다. 긴 목록은 내부에서 스크롤하며, 직접 입력도 가능하다. 이체에서는 카테고리 선택을 숨긴다.

목록에서 고르면 직접 선택 모드로 전환해 늦은 AI 응답을 무시한다. 선택만으로 기록을 저장하거나 사용처 기억을 만들지 않는다. 화살표/입력의 방향키로 목록을 열고 목록에서 방향키·Home·End·Enter로 고를 수 있다. Escape는 목록만 닫고, 바깥 클릭·종류 전환·기록 창 닫기도 목록을 닫는다. `tests/record-ui-browser.py`에서 이 흐름과 320~1440px 화면을 확인한다.

## 주식 카테고리

- 기본 지출 분류에 ‘주식’을 추가하여 미분류 포함 14개를 제공한다. 수입 분류는 기존 5개를 유지한다.
- 사용처 또는 내용의 ‘키움자동충전’, ‘키움 자동 충전’, ‘키움증권’, ‘KIWOOM’, ‘주식’, ‘국내주식 매수’, ‘해외주식 투자’ 등을 주식으로 인식한다. 일반 ‘자동충전’이나 회사 형태를 뜻하는 ‘주식회사’만으로는 주식으로 판단하지 않는다.
- 개인이 기억시킨 분류와 구체적인 구매 내용의 우선순위는 유지한다. 거래 종류를 자동으로 바꾸거나 기존 기록을 일괄 변경하지 않는다.
- **주식은 카테고리이며 거래 종류와 별개다.** 지출로 저장하면 기존 정책에 따라 예산·소비 합계에 포함된다. 내 증권계좌로 옮긴 충전금은 ‘내 계좌 간 이체’를 선택해야 소비 합계에서 제외된다. 주식 자동분류 안내에도 이 선택을 설명한다. 내부 이체의 저장 카테고리는 기존대로 ‘내부 이체’다.
- 기존 ‘키움자동충전’ 미분류 기록을 바꾸려면 기록을 열고 ‘자동 분류로 다시 보기’를 누른 뒤 저장한다. 거래 종류도 함께 확인한다.

## 직접 수정과 사용처 기억

- AI가 ‘새 카테고리를 추가할까요?’라고 물으면 ‘추가할게요’ 또는 ‘기존 분류로 둘게요’를 선택한다. 미응답 상태에서는 기록 저장 전에 선택을 안내한다. 직접 다른 분류를 고르는 방법도 가능하다.
- 승인한 새 이름은 ‘추가 예정’으로 표시하고 기록을 저장할 때 함께 저장한다. 창을 닫으면 추가도 취소된다. 승인 없이 기존 목록에 없는 이름을 AI가 바로 적용할 수 없다.
- 새 카테고리는 수입/지출별로 구분하고, 기존 이름과 같은 의미의 공백·기호 차이는 중복 생성하지 않는다. 추가된 항목은 다음 기록의 목록과 AI 허용 분류에 반영된다.

- 자동 결과는 입력창에서 바꿀 수 있다. 직접 수정하면 해당 입력 중에는 자동 결과로 덮어쓰지 않는다.
- ‘이 사용처는 다음에도 …로 기억하기’를 선택한 경우에만 개인 규칙을 저장한다. 선택하지 않으면 이번 기록에만 적용한다.
- 사용처는 유니코드 정규화·대소문자·공백·기호·일부 법인 접두사를 정리하여 비교한다. 지점명은 유지하므로 다른 지점에 무조건 확장하지 않는다.
- 지출과 수입 규칙은 분리한다. 내부 이체 규칙은 만들지 않는다.
- 기억해 둔 분류가 적용되면 ‘기억한 분류’ 배지를 표시한다.
- ‘이 사용처 기억 해제’는 현재 기록을 저장할 때 적용한다. 창을 닫으면 해제도 취소된다.
- 기존 기록은 일괄 재분류하지 않는다. 기존 기록을 열어 금액만 고쳐도 저장된 분류를 유지한다. ‘자동 분류로 다시 보기’를 누르거나 기존 자동 분류 기록의 사용처·내용을 바꿨을 때 새 판단을 적용한다.
- 개인 규칙을 추가·변경·삭제해도 과거 기록은 바꾸지 않는다.

## 데이터와 동기화

- 기록에 선택적 `description`과 `categorySource`를 추가한다. 이전 기록도 그대로 읽힌다.
- `categorySource`: keyword / merchant-rule / manual / unclassified / transfer / ai.
- AI는 기본 동작이다. 이전 버전의 `settings.aiCategorization`은 호환성을 위해 읽되 사용 여부를 결정하는 데 쓰지 않는다.
- 승인한 새 카테고리는 `settings.customCategories`에 종류·이름·수정 시각으로 저장하고, 항목별 `customCategory:{종류}:{정규화이름}` settings 패치로 동기화한다. 다른 기기에서 서로 다른 항목을 추가해도 배열 전체를 덮어쓰지 않는다. Firestore 접근 권한 확대는 필요 없다.
- 개인 규칙은 `settings.categoryRules`에 보관한다. 규칙은 종류·정규화 사용처·표시용 사용처·카테고리·수정 시각을 가진다.
- 동기화는 규칙마다 `table: settings`, `key: categoryRule:{종류}:{사용처}`로 분리하여 전송한다. 다른 기기에서 서로 다른 사용처를 기억시킨 경우 하나의 배열로 덮어쓰지 않는다.
- 기존 Firestore 보안 규칙의 settings 문서 범위 안에서 저장하므로 새 콘솔 설정이나 권한 확대가 필요하지 않다. 기존 UID별 접근 규칙이 그대로 적용된다.
- 기억 해제는 해당 규칙 문서의 value를 null로 기록한다. 증분 조회에서 다른 기기의 삭제도 반영한다.
- 기존 시트 연결을 사용하는 경우 거래내역 탭의 기존 10열 뒤에 내용·분류방식 2열을 추가한다. 기존 행과 첫 10열은 유지한다. 기존 미지원 열이나 다른 헤더가 있으면 자동 덮어쓰지 않고 중지한다.
- 직접 기록 수정/삭제, 예산 집계, 내부 이체 제외 규칙은 변하지 않는다.

## 검증

```sh
npm test
npm run check
npm run build
npm run preview
# 별도 터미널
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/category-browser.py
```

브랜드 분류, 구매 내용 우선, 여러 용도 섞임, 미분류, 수입·이체, 정확한 사용처 범위, 한 번만 수정, 명시적 기억, 기억 해제 취소/확정, 기존 기록 유지, 설정 변경·재접속, 기기 간 규칙 병합과 기존 시트 호환을 검증한다. 자동 브라우저 테스트는 개인 기록 대신 테스트 데이터를 사용한다. 실제 Firebase 사용자 데이터에는 접근하지 않는다.
