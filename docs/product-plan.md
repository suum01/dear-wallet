# Dear Wallet 제품 기획

사용자와 함께 결정한 내용. 기록은 내가 하고, 분류와 돌아보기는 앱이 돕는 개인 가계부. 모바일에서 편하게 쓰는 반응형 웹을 먼저 만들고, 이후 설치형 웹앱(PWA)으로 발전시킨다.

## 문제와 원칙

- 카테고리를 고르느라 기록을 포기하지 않도록 금액·사용처·날짜만으로 저장한다. 날짜 기본값은 오늘이다.
- 자동 분류는 저장을 막지 않는다. 확신이 없으면 미분류로 저장하고, 수정 이력을 학습한다. 사용처 규칙은 이번만/앞으로도 선택한다.
- 이유는 카테고리와 별개다. 태그·직접 입력 모두 가능하며 필수로 강요하지 않는다.
- 수동 기록이 기본이고, 밀렸을 때만 파일 가져오기로 복귀할 수 있다.
- 은행 거래의 '이체'라는 표기만으로 소비 합계에서 제외하지 않는다. 내 계좌 사이의 이동만 내부 이체이고, 타인에게 보내는 돈은 기본적으로 지출이다.
- 실제 사용자가 남긴 내용으로 분석하며, 미기록된 이유를 추측해 단정하지 않는다.
- 심플하고 귀여운 연노란색 디자인. 작은 화면, 큰 금액, 긴 한글, 확대 보기, 키보드·스크린리더 사용을 고려한다.

## 정보구조(IA)

모바일 하단 메뉴: 홈 / 내역 / 돌아보기 / 예산. 설정은 상단. 기록 버튼은 접근하기 쉬운 고정 위치에 둔다. 데스크톱에서는 사이드바를 사용한다.

## 공통 집계 규칙

- 한 달은 달력 기준(1일~말일) 또는 월급날 기준(예: 25일~다음 달 24일) 중 선택한다.
- 29~31일이 없는 달에는 해당 월 말일을 시작일로 삼는다. 기간과 원본 기록 날짜를 구분한다.
- 금액은 정수 원화로 처리하고 지출/수입/내부 이체를 명시적으로 구분한다.
- 내부 이체는 수입·지출 합계와 소비 예산에서 제외한다. 수수료는 별도 지출이다.
- 환불은 원래 지출과 연결하여 순지출에 반영하는 기능을 추후 구현한다. 타인에게 받은 돈도 정산·환불 여부를 확인할 수 있어야 한다.
- 신용카드 사용 시점의 소비와 결제대금 출금을 구분해 소비를 두 번 세지 않는다(추후 계좌 기능과 함께 구현).

## 홈

1. 한국 시간 기준 오늘 날짜와 인사말.
2. 현재 집계 기간과 예산 원.
   - 원은 테두리를 따라 12시에서 시작해 시계 방향으로 채워진다.
   - 예산 설정 전: 항상 가득 찬 원, 가운데에는 이번 기간 쓴 돈. 기록할수록 금액만 증가한다.
   - 예산 설정 후: 가운데 사용률, 테두리는 사용 비율. 기록할 때 기존 지점에서 새 지점으로 부드럽게 이동한다.
   - 초과: 테두리는 가득 찬 상태, 가운데 실제 비율(예: 112%), 초과 금액 표시.
   - 예산 없음과 0% 사용은 서로 다른 상태다. 원을 누르면 예산 설정·수정.
3. 전체 예산, 지출, 남은 예산, 남은 일수.
4. 마음 편히 쓸 수 있는 돈 = 전체 예산 − 현재 지출 − 아직 결제되지 않은 예정 고정비.
   - 이미 지출에 반영된 고정비는 다시 차감하지 않는다.
   - 음수이면 부족 금액을 명시한다. 수입은 지출 예산을 자동 증액하지 않는다.
5. 기간 경과율과 지출 사용률을 사실 중심으로 비교. 초반 고정비를 과소비로 단정하지 않는다.
6. 필요한 안내 하나. 분류 확인, 밀린 내역 가져오기, 리포트 등 상황에 맞게 변경(추후).
7. 매일 다른 금융 상식: 짧은 본문, 공식 출처, 저장. 검토한 목록을 순환하고 금융 제도는 기준일과 최신성 관리. 현재 목록은 7일 순환하며 링크는 공식 기관 안내 진입점이다.
8. 언제든 접근 가능한 기록 버튼.

**홈에는 최근 기록 3개 목록을 넣지 않는다.**

## 내역 — 달력 중심 (날짜 조회·기록 추가·수정·삭제·삭제 취소 구현, 나머지 후속)

- 날짜마다 지출 합계와 수입 합계를 구분해서 표시. 거래가 없는 합계는 생략한다.
- 내부 이체는 일별 합계에서 제외한다.
- 날짜를 누르면 바텀 시트에 그날의 합계와 개별 기록을 표시한다. 내부 이체도 합계 제외라는 표시와 함께 목록에는 남긴다.
- 바텀 시트에서 기록 선택 → 상세·수정. '이 날짜에 기록'으로 선택한 날짜를 자동 입력한다.
- 달력은 1일~말일로 유지하며 현재 예산 기간을 배경으로 강조한다. 월을 넘겨도 기간을 알 수 있게 한다.
- 사용처 검색과 카테고리·이유·계좌·입력 방식 필터. 필터 합계는 전체 합계와 구분한다.
- 수정 항목: 금액, 날짜, 사용처, 종류, 분류, 이유, 메모, 선택적인 결제수단. 삭제 후 실행 취소.
- 미분류도 지출 합계와 예산 사용률에 포함한다.

### 밀린 기록 가져오기

파일 선택 → 계좌/기간 확인 → 중복·내부 이체 후보 검토 → 반영 전 실제 지출 증가분 확인 → 저장. 처음에는 사용자의 금융사 CSV/엑셀 형식 하나부터 지원한다.

- 직접 입력과 파일 기록의 중복은 하나로 연결한다.
- 내 계좌로 확인된 입출금만 내부 이체 후보로 묶는다. 단지 금액이 같다는 이유로 제외하지 않는다.
- 불확실한 항목만 검토하도록 하고 임의 삭제하지 않는다.
- 가져오기 단위 취소를 제공한다.

## 돌아보기 (요약·원그래프·기간 조회 구현, 나머지 후속)

기간 선택(기본은 설정한 한 달) → 전체 요약 → 지출/수입 그래프 → 기간 비교 → 이유 분석 → 예산 비교 → 리포트와 회고.

- 구현: 수입, 지출, 수입−지출 표시. 차액을 실제 계좌 잔액이라고 부르지 않는다.
- 구현: 카테고리별 지출 도넛과 수입 도넛을 모바일에서 위아래 배치. 중앙 총액, 금액·비율 목록. 많은 항목은 ‘나머지 N개’로 묶고 펼칠 수 있다. 미분류·사용자 분류·기록 없는 상태를 포함한다.
- 구현: 달력/월급날 기준의 이전·다음·이번 기간 조회. 집계와 검증 세부는 [돌아보기 문서](review.md)를 참고한다.
- 후속: 그래프 조각/항목을 누르면 해당 내역 바텀 시트.
- 지난 기간과 카테고리별 비교. 진행 중에는 지난 기간의 같은 경과 시점과 비교하며 기간 길이 차이를 명시한다.
- 지출 이유는 가로 막대로 표시. 이유를 남긴 건수와 전체 건수를 함께 보여 분석의 한계를 드러낸다.
- 예산이 있을 때만 카테고리별 예산/실제/차이 표시. 초과 이유를 선택적으로 남긴다.
- 기록에 근거한 짧은 리포트, 만족·아쉬움 메모, 다음 기간 바꿀 행동 하나. 예산 화면으로 연결.

## 예산

전체 목표 → 고정비 확인 → 선택적인 카테고리 배분 → 사용 중 조정 → 회고 → 다음 기간 제안.

- 첫 설정은 전체 예산 하나면 충분. 설정 없이 기록 가능.
- 고정비 이름, 예상 금액, 매월 예정일. 변동하는 공과금은 예상 금액을 쓰고 실제 결제 후 수정.
- 예정일만으로 지출을 자동 생성하지 않는다. 실제 지출 또는 가져온 거래에 연결해서 결제 완료.
- 전체 예산 안에서 원하는 카테고리만 배분. 미배분 금액 유지. 카테고리 예산을 전체 예산에 중복 가산하지 않는다(후속).
- 예산 조정 가능. 첫 목표와 변경 이력·선택적 이유를 남기고 리포트에서 구분(후속).
- 3개월 정도 충분한 데이터가 쌓이면 예상 지출과 목표 예산을 구분해 제안. 누락·일회성·예정 큰 지출 고려. 사용자가 확정(후속).
- 코칭 말투는 다정/단호 등 선택. 임박·초과 시 행동을 제안하고, 무조건 비난하지 않는다(후속).

## 계좌 잔액 대조 — 이후 확장할 선택 기능

기본 꺼짐. 설정에서 켜기 → 관리할 계좌 → 기준 날짜/잔액 등록. 내역에 계좌 잔액 진입점이 나타난다. 끄면 기능만 숨기고 데이터는 보존. 내부 이체 소비 제외 규칙은 켜짐 여부와 무관하다.

예상 잔액 = 시작 잔액 + 입금 − 출금. 실제와 같은 시점으로 비교한다. 차액만으로 원인을 확정할 수 없으며, 은행 기록이 있으면 누락·중복·금액 오류·한쪽 이체·수수료 후보를 찾는다. 원인 미확인 차액을 임의 지출로 덮지 않는다. 모든 입출금, 신용카드 결제 구분이 필요하므로 이번 구현에서 제외한다.

## 첫 구현 범위와 단계

**구현:** 반응형 홈·캐릭터 로딩, 샘플 모드, 기록 추가/수정/삭제, AI 자동 분류와 새 카테고리 확인·사용처 기억, 달력 조회, 돌아보기 요약·두 원그래프·기간 조회, 전체 예산·고정비 연결, 일별 상식, 계정/시트 저장, JSON 내보내기.

**다음:** 돌아보기 상세 내역·기간 비교·이유 분석·리포트 → 예산 배분/이력 → 파일 가져오기 → 데이터 기반 예산/코칭 → 선택적 잔액 대조.

서버 저장·로그인·기기 동기화는 Firebase 연결 단계에서 구현했다. Google AI 분류 연결과 기기 내 키워드 대체 경로, 명시적인 사용처 기억을 지원한다. 월간 AI 리포트와 완전한 PWA 오프라인 캐시는 후속 작업이다. 개인 금융 데이터와 비밀 값은 GitHub에 올리지 않는다.

## 단계별 진행 방식

화면과 작은 동작을 먼저 구현하고 검증한 뒤 범위를 넓힌다. 돌아보기 첫 단계는 전체 요약과 지출·수입 도넛이며 기간 조회와 항목 펼치기를 함께 제공한다. 다음에는 비교·분석·리포트를 작은 기능 단위로 추가한다. 기존 기록과 사용자의 비공개 시트는 유지한다.

## Google Sheets 연결 구현

설정에서 OAuth 로그인과 기존 시트 확인, 로컬 기록 합치기 또는 원격 기록 불러오기를 선택할 수 있다. 지정된 탭·열과 기본 카테고리를 준비하고, 원본 탭을 지우지 않는다. 기록·예산·고정비·설정은 변경된 ID/키 단위로 전송한다. 실제 계정 로그인은 배포 후 사용자 브라우저에서 확인해야 한다. 자세한 구조와 제약은 [Google Sheets 연결](google-sheets.md)에 기록했다.

## 계정 로그인 단계

Google 계정으로 로그인한 뒤 본인 계정의 데이터를 읽고 홈 또는 요청한 화면으로 이동한다. 신규 사용자는 집계 기준 선택을 거친다. Firebase Authentication·Firestore의 실제 SDK와 UID 소유자 보안 규칙을 사용하며 사용자가 Google 로그인 동작을 확인했다. 자동화된 계정 분리 검증은 모의 어댑터로 진행한다. 기존 시트·로컬 기록은 사용자가 가져오기를 선택해야 계정에 합친다. [상세 검증 범위](firebase-login.md)를 참고한다.

## 사용처·내용 자동 분류 구현

입력 중 분류 결과를 표시하고, 구매 내용이 구체적이면 사용처의 일반 용도보다 우선한다. 애매하거나 여러 용도인 지출은 미분류로도 저장한다. 직접 고친 분류는 이번만 적용하거나, 명시적으로 사용처 규칙으로 기억시킨다. 개인 규칙은 같은 계정의 기기 간 동기화하며 과거 기록은 자동 재분류하지 않는다. [구현과 한계](categorization.md)를 참고한다.
