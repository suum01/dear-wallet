# Google Sheets 연결

현재 배포는 GitHub Pages의 정적 웹앱이며, Google Identity Services의 OAuth 팝업과 Google Sheets API를 브라우저에서 직접 사용합니다. 별도 백엔드·서비스 계정·공개 시트·OAuth client secret이 필요하지 않습니다. 공개 클라이언트 ID는 `src/google-config.js`에 있습니다. 개인 시트 주소·ID는 소스에 넣지 않고 각 사용자가 설정에서 입력합니다.

## 사용자 연결 순서

1. 앱 상단 설정 → **구글 시트와 함께 쓰기**로 이동합니다.
2. 기존 시트 주소 또는 ID를 확인합니다. 처음 연결할 때는 주소 또는 ID를 직접 입력합니다. 이미 연결한 기기는 그 기기에 저장된 연결 정보를 사용합니다.
3. **구글 로그인 · 시트 확인**을 누르고 시트를 편집할 수 있는 계정으로 로그인합니다.
4. 표시되는 실제 시트 이름과 기록 수를 확인합니다. 이 단계에서는 시트 내용을 바꾸지 않습니다.
5. **이 기기 기록도 합쳐서 연결** 또는 **시트 기록만 불러와 연결**을 선택합니다. 기존 로컬 기록은 연결 전에 `dear-wallet.beforeSheets.<시각>` 로컬 저장 키에 별도로 복사합니다.
6. ‘시트 저장 완료’ 상태를 확인합니다. 다른 기기에서는 같은 시트를 지정해 로그인하고 보통 ‘시트 기록만 불러와 연결’을 선택합니다.

새로 추가·수정·삭제한 기록, 예산, 고정비, 설정, 상식 북마크는 로컬 저장 후 약 1초 뒤 자동으로 전송합니다. 다른 기기의 변경은 **지금 동기화**를 누르거나 앱을 다시 앞으로 가져올 때 읽습니다. 실시간 스트리밍 방식은 아닙니다. 동기화 중 입력된 새로운 변경도 유지하여 후속 요청으로 전송합니다.

다시 열면 구글 로그인이 필요합니다. 재로그인 전의 새 기록은 이 기기에 남고 ‘시트 저장 대기’로 표시됩니다. 네트워크 오류·권한 만료 시에도 로컬 기록은 보존되며, 다시 로그인/동기화한 후에 완료 상태로 바뀝니다. 로그아웃 상태에서 브라우저 데이터를 삭제하면 미전송 기록을 잃을 수 있습니다. 연결 해제는 이 기기의 연결 설정만 지우고 로컬·원격 기록은 삭제하지 않습니다.

## Google Cloud 설정

- Google Sheets API 사용 설정.
- Google Auth Platform에서 앱 정보/연락처 설정.
- 개인 계정은 외부 앱의 테스트 모드로 시작하고, 실제 사용할 구글 계정을 테스트 사용자로 추가.
- 웹 애플리케이션 OAuth 클라이언트의 승인된 자바스크립트 원본: `https://suum01.github.io` (경로·끝 슬래시 제외).
- 로컬에서 실제 로그인까지 테스트하려면 해당 로컬 원본도 OAuth 클라이언트에 별도로 등록해야 합니다.
- 팝업 토큰 모델이므로 앱 코드에서 클라이언트 보안 비밀번호를 사용하지 않습니다.
- 요청 scope: `https://www.googleapis.com/auth/spreadsheets`. 이 권한은 Google 계정의 스프레드시트 전체에 대한 읽기·쓰기를 허용하는 범위입니다. 앱은 입력한 ID의 시트만 호출합니다. 향후 Picker와 `drive.file`을 사용하여 파일 단위 권한으로 좁힐 수 있습니다.
- access token은 JavaScript 메모리에만 보관합니다. `localStorage`, `sessionStorage`, JSON 내보내기, 저장소에 넣지 않습니다. 새로고침/만료 후에는 사용자 클릭으로 다시 승인받습니다.

로그인 창이 안 뜨면 팝업 차단 설정을 확인합니다. `origin_mismatch`는 승인된 원본, `access_denied`는 테스트 사용자/권한 승인, API 403은 Sheets API 사용 여부와 로그인한 계정의 시트 편집 권한을 확인합니다. 사용자의 실제 구글 로그인과 대상 시트 권한은 개발 환경의 모의 테스트로 검증할 수 없으므로 배포 후 본인 브라우저에서 확인해야 합니다.

## 탭과 저장 방식

기존에 만들어둔 탭은 유지합니다. 필요한 탭이 없으면 추가하고, 비어 있는 탭에는 열 제목을 넣습니다. 예상과 다른 열 제목이나 잘못된 금융 기록이 있으면 자동으로 덮어쓰거나 초기화하지 않고 연결을 멈춥니다. 관련 없는 탭은 읽거나 수정하지 않습니다.

| 탭 | 이번 버전에서 사용하는 열 |
| --- | --- |
| 거래내역 | 거래ID, 거래일, 종류, 금액, 사용처, 카테고리, 지출이유, 고정비ID, 수정시각, 삭제시각, 내용, 분류방식 |
| 기간별예산 | 기간시작일, 예산, 수정시각, 삭제시각 |
| 고정비 | 고정비ID, 이름, 예상금액, 매월예정일, 수정시각, 삭제시각 |
| 설정 | 항목, 값, 수정시각 |
| 카테고리 | 카테고리ID, 종류, 이름, 사용여부 — 빈 탭에만 기본 분류 추가 |
| 예산배분 | 예산ID, 카테고리ID, 금액 — 후속 기능용 열 제목만 준비 |

거래·예산·고정비·설정 변경은 **기존 행을 지우거나 전체 표를 교체하지 않고, 변경 이력을 새 행으로 추가**합니다. 같은 거래ID는 마지막 행을 현재 기록으로 사용하므로 수정 이력이 여러 행에 보일 수 있습니다. 행을 임의로 정렬·삭제하면 과거 내용이 현재 값으로 읽힐 수 있으므로, 조회용 필터 보기를 사용하고 수정·삭제는 앱에서 해주세요. 삭제시각이 있는 최신 거래는 집계에서 제외합니다. 설정 값은 JSON 텍스트입니다. 이번 카테고리는 거래에 이름으로 저장하며 카테고리 ID 연결은 후속 작업입니다.

서로 다른 거래ID의 추가는 유지합니다. **같은 ID를 두 기기에서 수정하면 마지막에 시트에 도착한 값이 적용**됩니다. 처음 연결에서 합칠 때는 이미 시트에 존재하는 ID와 기간 예산을 우선합니다. 별개 ID로 같은 소비를 두 번 입력한 경우에는 자동으로 중복으로 판정하지 않습니다. 내 계좌 간 이체 제외 규칙은 시트 연결 여부와 무관합니다.

각 저장은 단일 `spreadsheets.batchUpdate`로 처리합니다. 시트에 보내는 문자열은 `stringValue`로 기록하여 `=...`로 시작하는 사용처·메모를 수식으로 실행하지 않습니다. API 호출이 실패한 경우 완료로 표시하지 않습니다. 전송 완료 직후 응답 수신에 실패하여 재전송한 동일 ID 행은 이력으로 남을 수 있지만 집계에는 한 건만 반영됩니다.

## 검증

```sh
npm test
npm run check
npm run build
npm run preview
# 별도 터미널
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/sheets-browser.py
```

단위 테스트는 표 변환, 스키마 불일치, 두 기기 변경 합치기, 삭제, 네트워크 실패와 재시도, 미전송 변경 보존을 검증합니다. 브라우저 테스트는 **모의 Google OAuth와 모의 Sheets API**를 사용하며 실제 시트에 접근하지 않습니다. 실제 계정 로그인과 네트워크 권한은 배포 후 별도로 확인해야 합니다.

### 자동 분류 확장

거래내역의 기존 10열 형식도 읽을 수 있습니다. 다음 저장 시 내용·분류방식 열만 뒤에 추가합니다. 설정에는 `categoryRule:`로 시작하는 키별로 개인 사용처 규칙의 JSON 또는 삭제 표시 null이 저장됩니다. 임의의 기존 열을 덮어쓰지 않습니다.
