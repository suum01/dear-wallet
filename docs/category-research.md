# 가계부 5개 앱의 카테고리 조사

조사일: 2026-11-06. 목적: 분류를 고르는 피로를 줄이면서 지출 리포트에 쓸 수 있는 분류 체계와 자동분류 개선 방향을 정한다.

## 조사 범위와 방법

현재 환경에서 일반 고객센터 웹사이트 접속이 제한되어, 접근 가능한 **해외·오픈소스 가계부 5개**의 공식 공개 저장소에서 문서·기본 데이터·구현을 직접 확인했다. 앱을 설치하거나 로그인하여 체험한 조사는 아니며, 국내 주요 가계부 5개를 조사했다는 의미도 아니다. 확인하지 못한 서비스는 비교 수에 포함하지 않았다.

아래는 앱별로 근거의 성격을 구분한 결과다. 번역한 이름은 설명용이며 한국어판 화면의 실제 표기와 다를 수 있다. 저장소 개발 버전과 현재 배포 앱의 기본값도 다를 수 있어, 출처를 조사 당시 커밋으로 고정했다.

### 1. Cashew

기본 생성 코드에서 실제로 생성되는 지출 10개와 수입 1개를 확인했다. 교육·운동 생성 코드는 주석 처리되어 있어 활성 기본 카테고리 수에는 포함하지 않았다. 공식 소개의 Custom Categories와 Custom Titles에서는 사용자 정의 분류와 거래 이름별 분류 기억을 설명한다.

- [기본 카테고리 코드](https://github.com/jameskokoska/Cashew/blob/9cfbe50c16d95429891d44faf5f2c77a3abdb93b/budget/lib/struct/defaultCategories.dart)
- [영문 명칭](https://github.com/jameskokoska/Cashew/blob/9cfbe50c16d95429891d44faf5f2c77a3abdb93b/budget/assets/translations/generated/en.json)
- [공식 기능 소개](https://github.com/jameskokoska/Cashew/blob/9cfbe50c16d95429891d44faf5f2c77a3abdb93b/README.md)

### 2. Money Manager Ex

기본 SQL의 CATEGORY_V1 삽입 데이터에서 부모 ID를 통한 큰 분류·세부분류 연결을 확인했다. 예를 들어 Food → Groceries / Dining out, Automobile → Maintenance / Gas / Parking / Registration이다. 보험은 자동차·생명·주택·건강, 휴가는 여행·숙박·관광으로 세분화한다. 공식 소개에는 여러 단계의 중첩 카테고리를 지원한다고 명시되어 있다.

시드 데이터에 Transfer·Investment 등이 있다는 이유로 이를 Dear Wallet의 소비 지출 항목에 그대로 복사하지 않는다. 거래 종류와 소비 용도는 제품의 집계 정책에 맞춰 구분해야 한다.

- [기본 데이터 SQL](https://github.com/moneymanagerex/moneymanagerex/blob/d0d1eaab73e9b53dc04c54d6da2b68714f71b8bb/src/table/tables_en.sql)
- [카테고리 매뉴얼](https://github.com/moneymanagerex/moneymanagerex/blob/d0d1eaab73e9b53dc04c54d6da2b68714f71b8bb/docs/en_US/index.html)
- [다단계 분류 기능 소개](https://github.com/moneymanagerex/moneymanagerex/blob/d0d1eaab73e9b53dc04c54d6da2b68714f71b8bb/README.md)

### 3. My Expenses

공식 저장소의 영어 샘플 XML을 확인했다. 자동차에는 연료·수리·정비·주차·벌금이, Transport에는 버스·지하철·통행료·기차·트램·항공 등이 있다. 반려동물에는 사료·용품·미용·수의사, 자녀에는 돌봄·학업 등 생활 형태에 따른 항목도 있다. 수입 샘플은 급여·퇴직/연금·투자소득·기타 수입 등을 구분한다.

샘플의 음식·여가·휴가에는 서로 비슷한 용도의 항목도 있다. 분류 수를 그대로 늘리기보다 경계가 겹칠 때 어느 항목을 우선할지 정하는 편이 사용자에게 중요하다.

- [공식 샘플 분류 XML](https://github.com/mtotschnig/MyExpenses/blob/3e9cf57aa18bc08f140faa1443e3851ac85ace67/doc/categories-sample-src/categories_sample-en.xml)
- [앱 소개와 배포 링크](https://github.com/mtotschnig/MyExpenses/blob/3e9cf57aa18bc08f140faa1443e3851ac85ace67/README.md)

### 4. Actual Budget

공식 시작 가이드는 최소 기본 분류에서 시작해 필요에 따라 추가하라고 권장한다. 기본 Bills는 금액이 일정한 청구, Bills (Flexible)는 월별 금액이 변하는 청구를 뜻한다. 그룹은 사용자가 만들 수 있고 수입·지출 카테고리를 지원한다.

규칙 문서에는 사용처 정리와 카테고리 선택을 과거 행동에서 학습하여 규칙으로 저장하고, 사용자가 변경할 수 있다고 설명한다. 정확히 일치하는 사용처 조건과 일부 글자 포함 조건의 우선순위도 구분한다.

Actual의 Savings는 예산을 배분하는 항목이다. Dear Wallet에서는 저축용 내 계좌로 옮긴 돈을 소비 지출로 집계하지 않으므로, 이 명칭을 지출 기본값으로 복사하지 않는다.

- [기본 분류와 권장 그룹](https://github.com/actualbudget/actual/blob/92865f32f307ec04e0556a8c2052819d49e8e204/packages/docs/docs/getting-started/starting-fresh.md)
- [그룹·카테고리 관리](https://github.com/actualbudget/actual/blob/92865f32f307ec04e0556a8c2052819d49e8e204/packages/docs/docs/budgeting/categories.md)
- [자동분류 규칙과 학습](https://github.com/actualbudget/actual/blob/92865f32f307ec04e0556a8c2052819d49e8e204/packages/docs/docs/budgeting/rules/index.md)

### 5. Firefly III

공식 소개는 예산·카테고리·태그를 별개 기능으로 제시한다. 카테고리 모델은 사용자와 이름 등을 보관하며, SetCategory 규칙은 사용자 범위에서 해당 이름의 카테고리를 찾거나 만들고 거래에 지정한다. 이 조사에서 특정 식비·교통 목록이 모든 사용자에게 기본 제공된다는 근거는 확인하지 못했다.

Dear Wallet에서도 ‘쏘카’라는 사용처, ‘교통·차량’이라는 소비 용도, ‘제주 여행’이라는 맥락을 따로 저장하면 같은 지출을 두 번 집계하지 않고 여러 관점으로 돌아볼 수 있다. 이는 조사에 기반한 설계 제안이며 현재 구현된 태그 기능은 아니다.

## Dear Wallet에 제안하는 분류안

아래는 조사 결과를 바탕으로 한 **향후 제안**이다. 이번 수정에서 전체 카테고리나 기존 기록을 이 목록으로 바꾸지는 않는다. 사용자는 사용처·내용을 적고, 앱이 세부 용도를 제안하며, 홈 리포트에서는 큰 분류를 보여주는 방식을 권한다.

| 큰 분류 | 세부 용도 예시 |
| --- | --- |
| 식사·배달 | 외식, 배달, 구내식당 |
| 카페·간식 | 커피, 음료, 디저트, 즉석 간식 |
| 장보기 | 식재료, 집에서 먹을 식료품 |
| 교통·차량 | 대중교통, 택시, 카셰어링·렌터카, 주유, 주차·통행료, 차량 정비 |
| 주거·공과금 | 월세, 관리비, 전기·수도·가스 |
| 통신 | 휴대폰, 인터넷 |
| 생활용품 | 세제, 휴지, 주방·청소용품, 가구·가전 |
| 의류·잡화 | 옷, 신발, 가방, 액세서리 |
| 뷰티·미용 | 화장품, 미용실, 네일 |
| 의료·건강 | 병원, 약국, 검진 |
| 운동 | 헬스장, 필라테스, 운동 수업·용품 |
| 문화·취미 | 영화, 공연, 게임, 취미 활동, 오락용 스트리밍 |
| 교육·자기계발 | 강의, 학원, 교재·학습용 도서 |
| 여행·숙박 | 숙박, 여행사 패키지, 관광·입장료 |
| 경조사·선물 | 축의금, 조의금, 선물, 기부 |
| 보험 | 보장성 보험료 |
| 세금·수수료 | 세금, 은행 수수료, 대출 이자 |
| 기타 | 사용자가 용도를 알지만 다른 분류에 속하지 않는 지출 |

반려동물·육아·업무/사업비는 필요한 사람만 추가하는 선택 항목으로 제안한다. 수입은 급여, 부수입, 용돈·지원금, 이자·배당, 중고판매, 기타 수입 등 별도 체계가 적절하다. 환불·정산금의 집계 정책은 수입 항목을 늘리기 전에 별도로 정해야 한다.

### 경계가 겹칠 때의 기준

- 마트·쿠팡·편의점은 상점 이름만으로 식비를 확정하지 않는다. 무엇을 샀는지를 먼저 본다.
- 외식과 장보기는 바로 먹은 식사인지, 집에서 쓸 식료품인지로 나눈다. 모호한 경우 사용자의 기존 선택을 우선한다.
- 여행 중 쏘카는 교통·차량, 여행 중 식사는 식사·배달로 두고 ‘제주 여행’ 같은 맥락은 향후 태그로 묶는다. 태그 리포트와 용도 리포트 금액을 합산하지 않는다.
- 넷플릭스는 문화·취미이며 ‘구독/고정비’ 여부는 별도 속성이다. 구독이라는 이유만으로 모든 소비 용도를 한 분류에 몰지 않는다.
- **미분류**는 앱이 아직 모르는 상태이고, **기타**는 사용자가 다른 항목에 맞지 않는다고 결정한 분류다. 둘을 구분한다.
- 내 계좌 간 이체, 저축·투자를 위한 내 자산 이동은 소비 지출에서 제외한다. 타인에게 보낸 돈은 거래 용도에 맞는 지출로 기록한다. 대출 원금 상환도 소비 용도와 분리할 필요가 있다.

## 쏘카 미분류 원인과 이번 수정

카테고리 ‘교통’은 이미 있었지만 쏘카와 카셰어링 관련 인식어가 빠져 있었다. 분류 항목을 늘리는 작업과 브랜드·표현을 알아보는 작업은 별개다.

이번 수정은 사용처와 내용 양쪽에서 쏘카/SOCAR, 그린카/GreenCar, 카셰어링·카쉐어링, 렌터카·렌트카, 차량/자동차 대여를 기존 **교통**으로 인식하도록 보완한다. 구체적인 구매 내용과 개인이 명시적으로 기억시킨 분류의 우선순위는 유지한다. 여러 용도가 섞이면 미분류로 남기며 거래 종류를 임의로 바꾸지 않는다.

기존 미분류 기록은 해당 기록을 열어 **자동 분류로 다시 보기 → 수정 저장**으로 반영한다. 전체 세부분류 체계·태그·과거 기록의 일괄 재분류는 이번 변경에 포함되지 않는다.
