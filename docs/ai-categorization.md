# AI 자동 분류 연결

## 구현한 것과 아직 확인해야 할 것

Firebase JS SDK에 포함된 `firebase/ai`와 Firebase AI Logic의 Gemini Developer API 경로를 사용한다. 기존 Firebase 프로젝트 `dear-wallet-96f8c`를 그대로 사용하며 별도 서버나 Cloud Functions는 추가하지 않는다. Gemini 비밀 API 키를 소스·브라우저·GitHub에 넣지 않는다. Firebase AI Logic 설정 과정에서 관리되는 Gemini 키는 Google의 게이트웨이에서 사용한다. 기존 Firebase 웹앱 설정은 공개 클라이언트 설정이다.

코드와 모의 모델 응답을 사용하는 자동 검증을 완료해도 실제 프로젝트의 AI 서비스 활성화, 모델 제공 여부, 할당량, 실제 생성 결과의 검증과는 다르다. 이 환경에는 Firebase 관리자 자격 증명이 없고 AI 게이트웨이 접속도 네트워크 허용 범위에 포함되지 않는다. 따라서 콘솔 설정이나 실제 Gemini 호출 성공을 완료했다고 주장하지 않는다.

## 프로젝트 소유자의 최초 설정

1. [Dear Wallet Firebase 콘솔](https://console.firebase.google.com/project/dear-wallet-96f8c/overview)을 연다.
2. 메뉴에서 **AI Logic**을 찾고 **시작하기**를 선택한다. 메뉴 위치는 콘솔 버전에 따라 바뀔 수 있다.
3. **Gemini Developer API**를 선택하고 안내에 따라 관련 API와 관리되는 Gemini API 키 설정을 마친다. Agent Platform/Vertex AI 백엔드는 이 구현에서 선택하지 않는다.
4. 프로젝트의 이용 가능 모델과 무료 할당량·요금 안내를 확인한다. 이 코드 변경은 요금제나 결제 설정을 바꾸지 않는다. 모델은 `src/ai-categorizer.js`의 `AI_MODEL`에서 관리하며 최초 값은 `gemini-2.5-flash-lite`다. 프로젝트에서 해당 모델을 제공하지 않으면 사용 가능한 텍스트·JSON 출력 모델로 이 값을 바꾸고 실제 호출을 다시 확인한다.
5. 공개 서비스의 접근 보호와 할당량은 Firebase의 AI Logic/App Check 설정에서 관리한다. 기존 앱에는 App Check 공급자 설정이 없으므로 App Check 강제를 켜려면 웹 앱 등록·공급자 구성과 SDK 초기화도 함께 해야 한다. 임의로 API 키 제한을 해제하지 않는다.

코드에 API 키를 복사하거나 GitHub Secrets에 Gemini 키를 저장하는 과정은 필요하지 않다. 기존 Firestore의 UID별 기록 접근 권한도 그대로 사용한다.

## 실제 사용 확인

1. [웹앱](https://suum01.github.io/dear-wallet/)을 새로고침하고 Google 로그인한다.
2. 기록 창을 연다. **AI는 기본으로 실행되며 켜는 버튼은 없다.** 샘플 모드·기기 로컬 모드에서는 AI를 호출하지 않는다.
3. 사용처 **씨유**, 내용 **반숙란**을 적고 잠시 기다린다. ‘AI’ 배지가 표시되는지, 식비가 제안되는지 확인한다. ‘자동’이나 ‘임시 분류’만 보이면 AI 성공으로 보지 않는다.
4. 내용을 **치약**으로 바꾸면 새 내용으로 분류하는지 확인한다. 편의점 이름만으로 무조건 식비를 고르지 않는지도 확인한다.
5. 저장·다시 열기·다른 기기에서 동기화했을 때 categorySource가 ai인 기록과 설정이 보존되는지 확인한다.
6. 직접 분류를 바꾸면 늦은 AI 응답이 덮어쓰지 않는지, 내 계좌 간 이체를 고르면 AI 호출 없이 합계에서 제외되는지 확인한다.
7. 기존에 맞는 분류가 없는 내용은 새 카테고리 이름과 이유를 추천하는지 확인한다. 예를 들어 반려동물 비용을 위한 항목이 없으면 ‘반려동물’을 제안할 수 있다. 제안 수락 후에도 저장 전에는 목록에 추가되지 않으며, 기록 저장 후 같은 계정의 다른 기기에서도 목록과 AI 분류에 반영되어야 한다.

모델 답변은 항상 맞는 것이 아니므로 직접 수정과 명시적인 사용처 기억 기능을 유지한다. 저장을 누를 때 AI 요청을 기다리는 중이면 즉시 요청을 시작하거나 진행 중인 요청을 기다린다. 연결 실패나 12초 제한을 넘기면 오류를 표시하고 키워드 임시 분류 또는 직접 고른 값으로 저장할 수 있다.

## 데이터와 호출 동작

- AI 전송 데이터는 공백을 정리한 사용처(80자 이하), 내용(200자 이하), 사용자가 선택한 수입/지출 종류, 추가한 카테고리 이름이다. 금액·날짜·지출 이유·계좌·프로필·전체 가계부는 전송하지 않는다. 사용자가 사용처/내용에 직접 적은 개인정보는 그 문자열에 포함되므로 전송된다.
- 모델의 처리에는 Google AI 이용약관·데이터 처리 정책이 적용된다. 앱에서 API 키가 감춰진다는 사실이 모델 제공자의 데이터 처리까지 없어진다는 뜻은 아니다.
- 매 타이핑마다 호출하지 않고 마지막 입력 뒤 약 0.9초 기다린다. 기존 키워드에서 이미 분류된 입력도 기본으로 의미 해석을 요청한다. 과거 거래를 DB에서 찾아 AI 응답으로 표시하지 않는다.
- 직접 수정한 분류·기존 저장 분류·개인 사용처 기억은 우선하며 이 경우 AI를 호출하지 않는다. 입력이 바뀌거나 창을 닫거나 계정이 바뀌면 이전 응답을 버린다. 응답·프롬프트 캐시는 저장하지 않는다.
- 입력 문장을 명령으로 취급하지 않도록 시스템 지시와 JSON 데이터로 나누고, 구조화 응답과 클라이언트 허용 목록 검증을 함께 사용한다. 모델은 거래 종류나 금액을 변경할 수 없다.
- 한 번 실패한 입력은 화면이 다시 그려질 때마다 재호출하지 않는다. ‘AI 분류 다시 시도’ 또는 새로운 입력으로 재시도한다.
- 키워드 경로를 쓴 결과에는 AI 배지를 붙이지 않는다. AI에 연결하지 못해도 기록 작성과 수정은 가능하다.
- `category`는 기존 목록으로 제한하고 `suggestedCategory`와 `suggestionReason`을 별도로 받는다. 새 이름은 40자 이하의 분류 이름인지, 현재 거래 종류에 적합한지, 기존 항목과 중복인지 검사한다. 여러 용도가 섞이거나 단지 판단하기 어렵다는 이유로 새 항목을 만들지 않도록 지시한다. AI 추천 품질은 실제 모델 호출로 별도 확인해야 한다.

자동 브라우저 검증은 Firebase 계정 저장과 AI 응답 어댑터를 모의로 사용한다. 실제 Google 로그인·Gemini 모델 품질·실제 요금은 검증하지 않는다. 실제 호출 여부는 위의 프로젝트 소유자 확인 과정과 Firebase AI Logic 모니터링에서 확인한다.
