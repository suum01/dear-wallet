# 공개 코드와 개인정보

## 저장소에서 제거한 정보

- 개인 구글시트 ID와 개인 시트 이름을 앱 기본값 및 테스트에서 제거했다. 새 시트 연결은 설정에서 사용자가 주소·ID를 입력한다. 기존 연결은 각 기기에 보관된 연결 정보를 사용한다.
- 테스트는 가상의 시트 ID·이름·계정과 모의 서비스를 사용한다. 실제 가계부나 인증 토큰을 테스트에 복사하지 않는다.
- 이후 커밋에는 GitHub noreply 작성자 이메일을 사용한다. 과거 커밋의 개인 이메일과 시트 ID는 일반 수정 커밋으로 지워지지 않는다. 제거하려면 기록 재작성과 강제 푸시가 필요하며 기존 커밋 주소와 기여 기록에 영향을 줄 수 있다. 이번 수정은 과거 기록을 재작성하지 않는다.
- Firebase의 Node용 간접 의존성 `@grpc/grpc-js`를 보안 수정 버전 1.14.7로 고정했다. 기존 1.9.16에 보고된 GHSA-m9gg-hp2v-232j 및 GHSA-f596-whhp-79r4를 해결한다. 이 앱은 브라우저 번들을 배포하며 gRPC 서버를 운영하지 않지만, 설치되는 의존성도 수정한다. Firebase SDK를 구버전으로 되돌리는 강제 자동 수정은 사용하지 않는다.

## 공개 설정과 비밀 키의 차이

`src/firebase-config.js`의 Firebase 웹앱 설정과 `src/google-config.js`의 OAuth 클라이언트 ID는 브라우저가 서비스에 연결할 때 쓰는 공개 식별자다. 환경 변수로 옮겨도 브라우저로 전달되므로 비밀이 되지 않는다. 이 값만으로 다른 사용자의 기록을 읽을 수 있게 허용해서는 안 된다.

서비스 계정 개인키, OAuth client secret, 실제 access/refresh token, 직접 호출용 Gemini/OpenAI 비밀 키는 브라우저 코드·GitHub·배포 파일에 넣지 않는다. 실제 비밀 키가 공개됐다면 현재 파일에서 지우는 것과 별도로 발급 서비스에서 폐기·재발급해야 한다.

Firebase AI Logic은 Google 게이트웨이를 사용한다. 현재 코드에는 직접 호출용 Gemini 비밀 키를 넣지 않는다. 로그인 여부를 브라우저에서 검사하는 코드만으로 외부의 AI 호출을 차단할 수는 없다.

## 서버에서 보호해야 하는 설정

- Firestore는 인증된 사용자 자신의 UID 경로만 접근할 수 있어야 한다. 저장소의 `firebase/firestore.rules`는 이 원칙을 적용하지만 실제 운영 프로젝트에 배포된 규칙은 콘솔에서 확인해야 한다.
- Firebase Authentication의 승인 도메인, Google 웹 키의 서비스/API 제한, OAuth 승인 원본을 실제 앱에 맞게 유지한다. 제한을 일괄 해제하지 않는다. HTTP 리퍼러 제한을 적용할 때에는 Firebase 인증과 AI Logic의 호환성을 확인한다.
- AI 무단 사용과 할당량 소진을 줄이려면 App Check를 등록·SDK 초기화·정상 호출 검증한 뒤 강제를 적용한다. 현재 앱에는 App Check 초기화가 없으므로 콘솔에서 강제만 먼저 켜면 정상 기능도 차단될 수 있다. 할당량과 결제 설정도 프로젝트 소유자가 확인한다.
- 개인 시트의 공유 범위는 Google Drive에서 관리한다. ID를 코드에서 지워도 이미 공개로 공유한 시트가 비공개로 바뀌지는 않는다.

이 환경에는 Firebase 관리자 권한이 없어 실제 운영 규칙·키 제한·App Check·시트 공유 설정을 변경하거나 적용 상태를 검증하지 않았다.

## 재유입 방지

```sh
npm run audit:public
npm test
npm run check
npm run build
```

`audit:public`은 Git이 관리하는 파일과 무시되지 않은 새 파일에서 비밀 키 형식·실제 이메일·개인 시트 링크·인증 파일을 검사한다. 가상 예제와 지정된 공개 Firebase 웹 키는 구분한다. 로그에는 발견 위치와 종류만 표시하고 값은 출력하지 않는다. GitHub Pages 워크플로에서 이 검사를 통과해야 배포한다. 빌드도 배포 대상 소스 파일을 검사한 뒤 공개 자산만 복사한다.

`.gitignore`는 환경 파일·인증 파일·가계부 내보내기·백업을 제외한다. 무시 규칙은 이미 커밋한 파일을 삭제하지 않는다. 자동 검사는 알려진 패턴을 확인하는 보조 수단이며 모든 개인정보·취약점을 검출하거나 과거 Git 기록을 정리하지는 않는다.
