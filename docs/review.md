# 돌아보기: 요약과 원그래프

첫 단계는 총수입·총지출·수입−지출, 카테고리별 지출/수입 도넛, 기간 선택이다. `#review` 주소와 모바일/데스크톱 메뉴에서 열 수 있다. 기존의 연노란색·연녹색 카드와 지갑 화면 톤을 유지한다.

## 집계 기준

- 홈과 같은 `getPeriod`를 사용한다. 달력 기준은 1일~말일, 월급날 기준은 설정일~다음 설정일 전날이다. 없는 29~31일은 해당 달 말일로 보정한다.
- 진행 중인 기간은 한국 시간 오늘까지 기록한 내역만 포함한다. 과거 기간은 해당 기간 전체를 보여준다. 다음 기간 버튼으로 현재 기간을 넘어갈 수 없다.
- 삭제한 기록·내 계좌 간 이체는 수입/지출에서 모두 제외한다. 다른 사람에게 보낸 돈을 지출로 기록한 경우 포함한다.
- 고정비의 미결제 예상액을 다시 더하지 않는다. 실제로 지출 기록한 금액만 포함한다. 주식 등 카테고리 이름으로 거래 종류를 바꾸지 않는다.
- 수입−지출은 두 합계의 차액이며 실제 계좌 잔액을 뜻하지 않는다.
- 이름이 비어 있거나 없는 지출 분류는 미분류, 수입 분류는 기타 수입으로 집계한다. 사용자 추가 분류와 현재 목록에 없는 예전 분류도 저장된 기록의 이름으로 표시한다.
- 차트 비율은 각 거래 종류의 합계가 분모다. 수입과 지출의 금액을 한 원그래프에 섞지 않는다.

## 차트와 기간 이동

- 모바일은 두 카드를 위아래로, 넓은 화면에서는 나란히 배치한다. 중앙 총액, 기록 수, 카테고리별 정확한 원 단위 금액과 비율 표를 함께 제공한다.
- 6개 이하 카테고리는 모두 표시한다. 그보다 많으면 큰 5개와 ‘나머지 N개’로 모으고, ‘카테고리 모두 보기’로 펼친다. 실제 ‘기타’ 분류를 임의로 합치거나 원본 데이터를 변경하지 않는다.
- 각 차트의 펼침 상태는 독립적이다. 날짜나 집계 기준을 바꾸면 접힌 상태로 돌아간다.
- 0원 차트는 빈 안내와 회색 원을 보여준다. 0으로 나눠 비율을 만들거나 가상의 지출·수입을 채우지 않는다.
- 아주 작은 항목도 금액을 보존하며 비율은 ‘0.1% 미만’으로 표시할 수 있다. 억 단위 이상인 중앙 표시만 ‘약 N억 원’으로 줄이고 표와 전체 요약에서는 정확한 금액을 보여준다.
- 색만으로 구분하지 않도록 이름·금액·비율 표를 제공한다. 카테고리 이름은 HTML로 해석하지 않는다.
- 이전/다음 기간, 이번 기간 이동과 페이지 탐색·다시 그리기는 가계부 데이터를 저장하거나 바꾸지 않는다. 기록 수정·삭제·계정/시트 동기화는 기존 render 경로로 즉시 반영한다.
- 새 기록은 돌아보기 상단의 ‘기록하기’를 사용한다. 모바일에서 중복되는 떠 있는 기록 버튼은 이 화면에서 숨겨 그래프를 가리지 않게 한다.
- 계정 종료·교체 시 조회 기간과 차트 펼침 상태를 초기화하고 이전 사용자의 금액·분류를 지운다. 인증 전에는 기존 로딩/로그인 보호를 유지한다.

## 후속 단계

그래프 항목에서 내역 바텀 시트 열기, 지난 기간과 비교, 이유 분석, 카테고리 예산 비교, 월간 리포트·회고는 아직 구현하지 않았다. 잔액 대조도 별도 후속 기능이다.

## 검증

```sh
npm test
npm run check
npm run build
npm run preview
# 다른 터미널
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/review-browser.py
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/history-browser.py
BASE_URL=http://127.0.0.1:4173/dear-wallet/ python tests/auth-browser.py
```

단위 검증은 홈 합계 일치, 종류별 비율, 미분류·사용자 분류, 삭제·이체·미래 제외, 윤년·월급날 경계, 항목 묶기, 큰 금액·아주 작은 비율과 원본 불변을 확인한다. 브라우저 검증은 격리된 가상 기록으로 320~1440px 화면, 수정·삭제 반영, 기간 기준 변경, 직접 경로 새로고침, 안전한 이름 표시를 확인한다. 계정 분리는 모의 Firebase 어댑터로 확인하며 실제 사용자 계정 기록이나 AI API는 사용하지 않는다.
